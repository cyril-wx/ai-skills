# 测试用例审查技能

## 功能描述
本技能用于审查测试用例的完整性、覆盖度和质量，确保测试用例能够有效地验证软件功能。

## 适用场景
- 新编写的测试用例质量检查
- 回归测试用例库的定期优化
- 测试用例评审前的预审查

## 审查流程

### 1. 接收测试用例
- 接收用户提供的测试用例文件或内容
- 支持多种格式的测试用例（如Excel、CSV、文本文件等）

### 2. 分析测试用例
- 检查测试用例的完整性（是否包含必要的字段）
- 评估测试用例的覆盖度（是否覆盖了所有关键功能）
- 分析测试用例的质量（是否清晰、可执行）

### 3. 生成审查报告
- 提供详细的审查结果
- 指出测试用例中的问题和改进建议
- 给出测试用例质量的评分

## 输入格式
- 测试用例文件路径或内容
- 项目需求文档（可选，用于评估覆盖度）

## 输出格式
- 审查报告（包含问题列表和改进建议）
- 测试用例质量评分

## 示例

### 输入示例
```
测试用例文件: /path/to/test_cases.xlsx
项目需求文档: /path/to/requirements.md
```

### 输出示例
```
# 测试用例审查报告

## 总体评分
85/100

## 问题列表
1. 缺少边界值测试用例
2. 部分测试用例描述不够清晰
3. 未覆盖所有功能点

## 改进建议
1. 添加边界值测试用例
2. 完善测试用例描述
3. 补充缺失的功能测试
```

## 常见问题

### Q: 如何处理不同格式的测试用例？
A: 本技能支持多种格式的测试用例，包括Excel、CSV、文本文件等。如果遇到不支持的格式，请先转换为支持的格式。

### Q: 如何评估测试用例的覆盖度？
A: 测试用例的覆盖度评估基于项目需求文档和功能规格说明。如果没有提供这些文档，将基于测试用例本身的内容进行评估。

### Q: 如何提高测试用例的质量？
A: 提高测试用例质量的建议包括：
- 确保测试用例描述清晰、准确
- 包含足够的边界值测试
- 覆盖所有关键功能点
- 提供详细的测试步骤和预期结果
